# Kunfupay-Payins

Independent **payment-in orchestration** platform. Split into two fully independent
repos under this umbrella:

| Repo | Path | Purpose |
|---|---|---|
| **Backend** | [`Kunfupay-Payins-Back/`](Kunfupay-Payins-Back/) | Hono service — domain core, REST API, inbound + outbound webhooks, crons. Deploys to Vercel as a serverless project. |
| **Frontend** | [`Kunfupay-Payins-Front/`](Kunfupay-Payins-Front/) | Internal pnpm workspace with the two Next.js apps (`apps/checkout`, `apps/dashboard`) + shared workspace packages (`api-client`, `types`, `money`). |

> **This umbrella is NOT a monorepo.** Each child repo is self-contained — it has its
> own `package.json`, lockfile, `.npmrc`, Docker, Biome config, Husky hooks, and
> deployment target. They can be cloned, installed, built, tested, and deployed in
> complete isolation.

The backend is **platform-agnostic** (DDD + Hexagonal + CQRS, UUID v7, Unix-ms
`BigInt` timestamps, integer minor-unit money, 100% test coverage). The frontends
consume the backend's HTTP API; the only seam is a typed client generated from the
backend's OpenAPI 3.1 spec.

## Clone (with both children)

The two child repos are registered as **git submodules**. Clone the umbrella
with `--recurse-submodules` so both are checked out in one command:

```bash
git clone --recurse-submodules git@github.com:danielsamaniego/payins.git Kunfupay-Payins
cd Kunfupay-Payins
```

If you already cloned without `--recurse-submodules`, hydrate them after the fact:

```bash
git submodule update --init --recursive
```

To pull the latest commits from each child's own `main`:

```bash
git submodule update --remote --merge
git commit -am "bump submodules"
git push
```

## Quick start (per repo)

```bash
# Backend
cd Kunfupay-Payins-Back
pnpm install
pnpm start:local      # Postgres + Redis in Docker → wait → schema → seed
pnpm dev              # Hono on :1464 (Postgres :1465, Redis :1468)

# Frontend (separate terminal)
cd Kunfupay-Payins-Front
pnpm install
pnpm dev              # turbo: checkout :1466 + dashboard :1467
                      # both apps default NEXT_PUBLIC_PAYINS_API_URL=http://localhost:1464
```

## Docker (per repo)

Docker is **scoped to each child repo** — there is no umbrella compose file. Each
repo carries its own `docker-compose*.yml`:

| Repo | Compose files | What they bring up |
|---|---|---|
| Backend | `docker-compose.yml`, `docker-compose.dev.yml`, `docker-compose.test.yml` | Postgres + Redis / + back hot reload / + back + stripe-mock for e2e |
| Frontend | `docker-compose.dev.yml` | checkout + dashboard with hot reload (expects back at `host.docker.internal:1464`) |

See each repo's own README and its own `docs/deployment.md` —
[back](Kunfupay-Payins-Back/docs/deployment.md) ·
[front](Kunfupay-Payins-Front/docs/deployment.md).

## Universal rules (apply to both repos)

These cross the seam between the repos and must stay consistent. Each child repo
restates them in its own `AGENTS.md`; if they ever drift, the umbrella
[`AGENTS.md`](AGENTS.md) § "Universal Rules" wins.

- Tenancy: `Platform` (API key) → one or more `Account`s; all account-scoped tables
  carry `platform_id` + `account_id` as `NOT NULL` FKs.
- Money: integer minor units (`BigInt` in back, `number` at API boundary and in
  fronts). No floats.
- Percentages: basis points integer (0–10000). No floats.
- IDs: UUID v7 only, generated by application code.
- Timestamps: Unix milliseconds (`number` everywhere, `BigInt` in DB).
- PCI: never accept or store PAN/CVV; only provider tokens.
- Consumer isolation: no file references "kunfupay", "sale", "order", "product".
